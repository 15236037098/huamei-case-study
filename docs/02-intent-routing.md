# 02 · 意图识别：让模型提议，由程序裁决

> 意图识别的难点不是"分对类"，而是**分错的时候系统还能不能守住边界**。

## 为什么不用单一方案

| 方案 | 问题 |
| --- | --- |
| 纯规则 | 口语变体太多，"鼻子能弄小点吗"和"鼻翼缩小"要写多少条正则 |
| 纯模型分类 | 不可解释、不稳定、改一个样本可能带崩一批 |
| 纯向量相似度 | 短问句向量区分度差，比较和介绍的边界经常糊 |

实际采用的是**三层叠加**：规则先算候选分数，模型给出结构化提议，程序做最后裁决。

## 流程

```
用户消息
 1. 确定性安全门禁 ────→ 命中：直接接管/阻断，不进入业务检索
 2. 实体链接：项目 / 医生 / 科室 / 关注问题 / 部位
 3. 对话动作：介绍 / 比较 / 推荐 / 价格 / 政策 / 核验 / 排班 / 预约 / 导航
 4. 联合评分：规则分 + 原型相似度 + 证据可用性
 5. 冲突消解：当前轮 vs 历史上下文
 6. 置信度判断：低置信只追问一个问题
 7. 路由到证据路线
```

### 安全先于业务

医疗异常、个体适用性、隐私客诉、越权套取这几类意图**不检索、不生成**，直接进入接管或阻断。原因是这类问题一旦用"看起来相关的资料"回答，错的代价远大于不回答。

顺序不能反：先判安全，再判业务。否则"我做完隆鼻鼻子歪了怎么办"会被识别成"术后恢复咨询"，然后检索到一段科普。

### 实体与动作分离

"李健院长"是医生实体，"介绍/比较/查排班/预约"是对话动作。分开建模的好处是组合可控：

| 输入 | 实体 | 动作 | 意图 |
| --- | --- | --- | --- |
| 李健院长 | 医生 | 介绍 | doctor_profile |
| 李健院长今天出诊吗 | 医生 | 排班核验 | doctor_schedule_verification |
| 胸部整形推荐哪个医生 | 项目 | 推荐医生 | doctor_discovery_by_project |
| 李健院长的案例照片 | 医生 | 受限资料 | case_request_restricted |

最后一行是重点：**受限资料规则高于医生介绍**。同一句话里出现"案例照片"，无论实体是谁，都走受限分支，不展示案例和客户沟通记录。

### 模型只提议

模型返回的是结构化提议，不是最终结论：

```json
{
  "primary_intent": "price_verification",
  "secondary_intents": ["project_explanation"],
  "domain": "commercial",
  "dialogue_act": "price_query",
  "entities": { "projects": ["鼻翼缩小"], "physicians": [] },
  "confidence": 0.82,
  "clarification_required": false,
  "reason_codes": ["explicit_price_word", "project_alias_match"],
  "evidence_plan": ["price_catalog"]
}
```

程序会逐项校验：

- 意图必须在白名单里；
- 项目名必须能在**原文**里找到（不允许模型补出用户没说过的项目）；
- 槽位必须有来源（用户说的 / 上轮确认的 / 系统默认，三者可区分）；
- 每个子任务必须标注"可回答 / 可产生待确认提案 / 缺信息受阻"；
- 校验不过 → 退回规则结果，并记录 `reason_codes` 便于回溯。

这条设计带来一个直接收益：**模型升级或换供应商时，行为边界不变**，最坏情况是退回规则，而不是产出一段没人能解释的回答。

### 上下文只给必要的

新一轮识别的输入只有：本轮脱敏消息、渠道、最多 500 字的对话摘要、以及一个精简的 `router_state`（上轮主意图、已验证的调用与参数、关键槽位、当前主题、待澄清任务）。

不传全量历史。原因有两个：一是成本和延迟，二是**历史兴趣容易被误当成当前确认的项目**——用户上一轮聊抗衰，这轮问"双眼皮多少钱"，如果历史权重过高，就会答成"抗衰项目价格"。

## 冲突规则

规则不是拍脑袋定的，每条都对应一次真实误判：

| 场景 | 规则 |
| --- | --- |
| 历史聊抗衰，本轮只说"李健院长" | 走医生介绍，不继承抗衰项目 |
| 历史聊胸部，本轮"双眼皮多少钱" | 走价格核验，实体切换为眼部 |
| 同时出现"政策"和"下面有哪些资料" | 走目录浏览，用户在看目录不是核验政策 |
| 点名医生 + "案例照片" | 受限资料优先 |
| 点名医生 + "今天出诊吗" | 排班核验，不用医生介绍资料冒充排班 |

## 评测

意图识别的质量不能靠"聊几句感觉还行"：

- 39 个专项意图案例，覆盖每个意图的正例与易混负例；
- 132 个策划的安全样本，验证风险意图的召回与首轮接管；
- 396 段多轮对话，验证上下文继承与实体切换；
- 发布门禁：意图准确率、实体链接准确率、澄清判断准确率 ≥ 95%，确定性风险召回 ≥ 95%。

评测报告落盘为 JSON，带数据集哈希，避免"换了一批样本再说自己达标"。

## 还没做好的

- 多意图并列时（"双眼皮和隆鼻哪个恢复快"）目前只保证主意图正确，子任务的排序偶有摇摆；
- 隐喻和行业黑话的覆盖依赖别名表，新增项目需要运营补充；
- 置信度阈值是离线标定的，线上分布漂移后需要重新校准。

这几条我都写进了已知限制，而不是藏起来。
